# 设备使用时间追踪系统 - 功能需求文档

## 1. 文档说明

本文档详细描述设备使用时间追踪系统的功能需求,包括客户端、后端和前端的功能模块。

## 2. 客户端功能需求

### 2.1 数据采集功能

#### 2.1.1 窗口监控
- **需求描述**: 实时监控Windows系统当前活跃窗口
- **实现方式**: 监听 `EVENT_SYSTEM_FOREGROUND` 事件
- **采集数据**:
  - 应用名称
  - 窗口标题
  - 格式: `应用名称（窗口标题）`
- **触发条件**: 窗口焦点变化时立即触发

#### 2.1.2 应用使用时长统计
- **需求描述**: 统计每个应用的使用时长
- **统计维度**: 
  - 按应用名称统计
  - 按天累计,每天0点重置
  - 0点前算前一天,0点后算后一天
- **精度要求**: 秒级精度
- **判定逻辑**: 
  - 窗口焦点切换时记录前一应用的结束时间
  - 记录新应用的开始时间
  - 应用关闭时停止计时

#### 2.1.3 键盘敲击计数
- **需求描述**: 统计键盘敲击次数
- **统计方式**: 累计计数
- **包含内容**: 所有按键操作
- **数据格式**: 整数值,如 `1250`

#### 2.1.4 鼠标点击计数
- **需求描述**: 统计鼠标点击次数
- **统计方式**: 累计计数
- **包含内容**: 
  - 左键点击
  - 右键点击
  - 滚轮点击
- **不包含**: 滚轮滚动
- **数据格式**: 整数值,如 `856`

#### 2.1.5 鼠标移动距离统计
- **需求描述**: 统计鼠标移动距离
- **统计方式**: 累计距离
- **包含内容**: 
  - 鼠标平面移动距离
  - 滚轮滚动距离
- **精度要求**: 保留两位小数,如 `23.01m`
- **单位**: 米(m)

### 2.2 数据上传功能

#### 2.2.1 增量上传机制
- **上传频率**: 每秒一次
- **上传方式**: HTTP POST请求
- **数据格式**: JSON格式增量数据
- **增量逻辑**:
  - 只上传有变化的数据
  - 如果某个应用的所有信息(时长、操作次数等)都没有变化,则不包含该应用
  - 已关闭的应用不再上传累计数据
  - 只上传当前活跃应用的增量数据

#### 2.2.2 断线重连机制
- **需求描述**: 网络中断时自动重连
- **重连策略**: 
  - 检测到连接失败后立即重试
  - 采用指数退避算法
  - 最大重试间隔不超过30秒
- **本地缓存**: 网络中断时将数据暂存本地,恢复后批量上传

### 2.3 用户配置功能

#### 2.3.1 用户登录
- **需求描述**: 用户使用邮箱和密码登录
- **登录验证**: 服务器验证后返回Token
- **Token管理**: 客户端本地存储Token,每次上传时携带

#### 2.3.2 配置管理
- **需求描述**: 管理客户端运行配置
- **配置项**:
  - 服务器地址
  - 上传频率
  - 数据保留策略
  - 开机自启动
  - 后台运行

## 3. 后端功能需求

### 3.1 用户管理功能

#### 3.1.1 用户注册
- **需求描述**: 用户通过邮箱注册账号
- **必填信息**: 
  - 邮箱地址(作为登录凭证)
  - 密码
- **验证机制**: 
  - 邮箱格式验证
  - 邮箱唯一性验证
  - 密码强度验证
- **注册成功**: 
  - 创建用户账号
  - 自动生成唯一秘钥

#### 3.1.2 用户登录
- **需求描述**: 用户通过邮箱和密码登录
- **认证方式**: JWT Token认证
- **Token有效期**: 7天(可配置)
- **Token刷新**: Token过期前自动刷新

#### 3.1.3 秘钥管理
- **秘钥生成**:
  - 长度: 不超过32位
  - 格式: 小写字母、大写字母、数字、常见符号混合
  - 要求: 全局唯一
- **秘钥查看**: 用户可在个人页面永久查看秘钥
- **秘钥重新生成**: 用户可重新生成新秘钥
- **秘钥作废**: 用户可作废当前秘钥

### 3.2 数据接收功能

#### 3.2.1 增量数据接收
- **接收方式**: HTTP POST接口
- **数据格式**: JSON格式增量数据
- **验证机制**: 
  - Token验证
  - 数据格式验证
  - 时间戳验证
- **处理流程**:
  1. 接收客户端上传的增量数据
  2. 验证用户Token
  3. 更新Redis中的热数据
  4. 触发WebSocket推送
  5. 返回成功响应

#### 3.2.2 数据存储策略
- **热数据存储**:
  - 存储位置: Redis
  - 保留时间: 近7天
  - 数据结构: Hash结构,Key为 `user:{userId}:{date}`
- **冷数据存储**:
  - 存储位置: MySQL
  - 保留时间: 永久
  - 表结构: 按日期分表

### 3.3 数据归档功能

#### 3.3.1 自动归档
- **触发方式**: 定时任务,每天凌晨执行
- **归档逻辑**:
  1. 查询Redis中超过7天的数据
  2. 将数据批量插入MySQL
  3. 删除Redis中已归档的数据
  4. 更新数据索引
- **错误处理**: 归档失败时记录日志,不影响实时数据

#### 3.3.2 数据压缩
- **需求描述**: 对历史数据进行压缩存储
- **压缩策略**: 
  - 按应用维度聚合
  - 压缩JSON数据
  - 减少存储空间占用

### 3.4 WebSocket推送功能

#### 3.4.1 WebSocket连接管理
- **连接建立**: 前端通过WebSocket连接后端
- **身份验证**: 连接时验证Token或秘钥
- **订阅机制**: 查看者订阅特定用户的数据
- **连接保活**: 心跳机制维持连接

#### 3.4.2 实时数据推送
- **触发时机**: 每次收到客户端数据立即推送
- **推送范围**: 所有订阅该用户的查看者
- **推送内容**: 完整的实时数据(包含所有应用的累计数据)
- **推送延迟**: 2秒以内
- **推送格式**: JSON格式消息

### 3.5 历史数据查询功能

#### 3.5.1 REST API查询
- **查询方式**: REST API GET请求
- **查询参数**: 
  - 用户ID或秘钥
  - 日期(YYYY-MM-DD格式)
- **返回数据**: 完整的当天数据汇总
- **数据来源**: 
  - 近7天: 从Redis查询
  - 超过7天: 从MySQL查询

#### 3.5.2 日历数据接口
- **需求描述**: 提供有数据的日期列表,用于前端日历展示
- **返回数据**: 用户有数据记录的所有日期
- **用途**: 前端日历组件标记有数据的日期

- **页面切换**: < 300ms

## 6. 数据字段说明

### 6.1 客户端上传数据格式

```json
{
  "userId": "string",           // 用户ID
  "timestamp": "2026-07-12T10:30:45Z",  // 时间戳
  "applications": [             // 应用列表(仅包含有变化的应用)
    {
      "name": "Chrome",         // 应用名称
      "windowTitle": "Google搜索", // 窗口标题
      "duration": 3600,         // 累计使用时长(秒)
      "isActive": true          // 是否当前活跃
    }
  ],
  "statistics": {
    "keyboardCount": 1250,      // 键盘敲击累计次数
    "mouseClickCount": 856,     // 鼠标点击累计次数
    "mouseDistance": 23.01      // 鼠标移动累计距离(米)
  }
}
```

### 6.2 WebSocket推送数据格式

```json
{
  "type": "realtime_update",    // 消息类型
  "userId": "string",           // 用户ID
  "timestamp": "2026-07-12T10:30:45Z",
  "data": {
    "applications": [           // 完整的应用列表
      {
        "name": "Chrome",
        "windowTitle": "Google搜索",
        "duration": 3600,
        "isActive": true
      },
      {
        "name": "VSCode",
        "windowTitle": "main.py",
        "duration": 1800,
        "isActive": false
      }
    ],
    "statistics": {
      "keyboardCount": 1250,
      "mouseClickCount": 856,
      "mouseDistance": 23.01
    }
  }
}
```

## 7. 业务规则

### 7.1 数据统计规则

1. **应用时长统计**:
   - 从窗口获得焦点开始计时
   - 窗口失去焦点时结束计时
   - 应用关闭时累计时长保留,但标记为"已关闭"

2. **跨天处理**:
   - 0点前的数据归属前一天
   - 0点后的数据归属后一天
   - 跨天使用的应用按实际时间分割

3. **增量上传规则**:
   - 只上传有变化的数据
   - 已关闭应用不再上传
   - 前端仍显示已关闭应用的累计数据

### 7.2 秘钥管理规则

1. **秘钥生成**:
   - 注册时自动生成
   - 全局唯一
   - 长度不超过32位

2. **秘钥操作**:
   - 重新生成: 旧秘钥立即失效,生成新秘钥
   - 作废: 旧秘钥立即失效,不生成新秘钥
   - 操作需用户确认

3. **秘钥使用**:
   - 无需登录即可使用
   - 仅限查看,不可修改
   - 不限制使用人数和次数

## 9. 附录

### 9.1 错误码定义

| 错误码 | 说明 |
|--------|------|
| 200 | 成功 |
| 400 | 请求参数错误 |
| 401 | 未授权(Token或秘钥无效) |
| 403 | 无权限访问 |
| 404 | 资源不存在 |
| 500 | 服务器内部错误 |

### 9.2 常见问题处理

1. **网络中断**: 客户端自动重连,本地缓存数据待恢复后上传
2. **Token过期**: 自动刷新Token,需重新登录时跳转登录页
3. **秘钥失效**: 显示提示,引导用户联系秘钥提供者
4. **数据加载失败**: 显示错误提示,提供重试按钮
