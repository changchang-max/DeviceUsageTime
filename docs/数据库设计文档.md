# 设备使用时间追踪系统 - 数据库设计文档

## 1. 文档说明

本文档基于《功能需求文档》、《前后端API文档》和《项目总体概述》设计数据库结构，支持用户管理、数据存储（热数据+冷数据）、秘钥管理等功能。

## 2. 数据库概述

### 2.1 存储策略

| 存储类型 | 数据库 | 用途 | 保留时间 |
|----------|--------|------|----------|
| 热数据 | Redis | 近7天的实时数据 | 7天 |
| 冷数据 | MySQL | 历史数据持久化 | 永久 |
| 用户数据 | MySQL | 用户账号、秘钥等 | 永久 |

### 2.2 技术选型

- **MySQL**: 8.0+，用于持久化存储
- **Redis**: 用于热数据缓存和Token黑名单

## 3. MySQL 数据库设计

### 3.1 用户表 (users)

存储用户基本信息和认证数据。

```sql
CREATE TABLE users (
    id BIGINT PRIMARY KEY AUTO_INCREMENT COMMENT '用户ID',
    email VARCHAR(255) NOT NULL UNIQUE COMMENT '邮箱地址，作为登录凭证',
    password_hash VARCHAR(255) NOT NULL COMMENT '密码哈希值（BCrypt加密）',
    secret_key VARCHAR(32) UNIQUE COMMENT '用户秘钥，全局唯一',
    secret_key_status TINYINT DEFAULT 1 COMMENT '秘钥状态：1-有效，0-已作废',
    nickname VARCHAR(100) DEFAULT NULL COMMENT '用户昵称（可选）',
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '注册时间',
    updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    last_login_at DATETIME DEFAULT NULL COMMENT '最后登录时间',
    status TINYINT DEFAULT 1 COMMENT '账号状态：1-正常，0-禁用',
    
    INDEX idx_email (email),
    INDEX idx_secret_key (secret_key),
    INDEX idx_created_at (created_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='用户表';
```

**字段说明**：
- `id`: 自增主键，全局唯一用户标识
- `email`: 登录凭证，唯一约束
- `password_hash`: BCrypt加密后的密码
- `secret_key`: 自动生成的秘钥，不超过32位，全局唯一
- `secret_key_status`: 支持秘钥作废功能

### 3.2 Token黑名单表 (token_blacklist)

用于Token失效管理（退出登录、Token刷新等场景）。

```sql
CREATE TABLE token_blacklist (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    token_jti VARCHAR(64) NOT NULL UNIQUE COMMENT 'JWT的唯一标识符（jti claim）',
    user_id BIGINT NOT NULL COMMENT '用户ID',
    expired_at DATETIME NOT NULL COMMENT 'Token过期时间',
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '加入黑名单时间',
    
    INDEX idx_user_id (user_id),
    INDEX idx_expired_at (expired_at),
    
    FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='Token黑名单表';
```

**设计说明**：
- 存储已失效的JWT Token标识
- 定期清理过期的黑名单记录
- 可选：也可使用Redis存储黑名单，性能更好

### 3.3 每日统计数据表 (daily_statistics)

存储用户每日的综合统计数据，按日期分区。

```sql
CREATE TABLE daily_statistics (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    user_id BIGINT NOT NULL COMMENT '用户ID',
    stat_date DATE NOT NULL COMMENT '统计日期',
    keyboard_count INT UNSIGNED DEFAULT 0 COMMENT '键盘敲击总次数',
    mouse_click_count INT UNSIGNED DEFAULT 0 COMMENT '鼠标点击总次数',
    mouse_distance DECIMAL(10, 2) DEFAULT 0.00 COMMENT '鼠标移动总距离（米）',
    scroll_distance DECIMAL(10, 2) DEFAULT 0.00 COMMENT '滚轮滚动总距离',
    total_duration INT UNSIGNED DEFAULT 0 COMMENT '设备总使用时长（秒）',
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    
    UNIQUE KEY uk_user_date (user_id, stat_date),
    INDEX idx_stat_date (stat_date),
    
    FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='每日统计数据表';
```

**字段说明**：
- 按用户+日期唯一约束，每天每个用户一条记录
- 存储当天的累计统计数据

### 3.4 应用使用记录表 (app_usage_records)

存储用户每个应用的使用详情。

```sql
CREATE TABLE app_usage_records (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    user_id BIGINT NOT NULL COMMENT '用户ID',
    stat_date DATE NOT NULL COMMENT '统计日期',
    app_name VARCHAR(255) NOT NULL COMMENT '应用名称',
    total_duration INT UNSIGNED DEFAULT 0 COMMENT '该应用当天总使用时长（秒）',
    sessions INT UNSIGNED DEFAULT 0 COMMENT '使用次数（会话数）',
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    
    UNIQUE KEY uk_user_date_app (user_id, stat_date, app_name),
    INDEX idx_user_date (user_id, stat_date),
    INDEX idx_app_name (app_name),
    
    FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='应用使用记录表';
```

**字段说明**：
- 记录每个应用每天的汇总数据
- `sessions`: 应用被切换到的次数

---

### 3.5 应用窗口标题表 (app_window_titles)

存储每个应用使用过的窗口标题列表。

```sql
CREATE TABLE app_window_titles (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    record_id BIGINT NOT NULL COMMENT '关联的应用使用记录ID',
    window_title VARCHAR(500) NOT NULL COMMENT '窗口标题',
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    
    INDEX idx_record_id (record_id),
    
    FOREIGN KEY (record_id) REFERENCES app_usage_records(id) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='应用窗口标题表';
```

**设计说明**：
- 一个应用可能使用过多个窗口标题
- 与 `app_usage_records` 是一对多关系
- 查询时可用 GROUP_CONCAT 聚合

### 3.6 验证码记录表 (verification_codes)

存储邮箱验证码信息。

```sql
CREATE TABLE verification_codes (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    email VARCHAR(255) NOT NULL COMMENT '邮箱地址',
    code VARCHAR(6) NOT NULL COMMENT '验证码',
    type TINYINT DEFAULT 1 COMMENT '类型：1-注册，2-登录，3-重置密码',
    expired_at DATETIME NOT NULL COMMENT '过期时间',
    used TINYINT DEFAULT 0 COMMENT '是否已使用：0-未使用，1-已使用',
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    
    INDEX idx_email_type (email, type),
    INDEX idx_expired_at (expired_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='验证码记录表';
```

**字段说明**：
- 验证码有效期5分钟
- 使用后标记 `used = 1`
- 定期清理过期记录

## 4. Redis 数据结构设计

### 4.1 实时数据存储

#### 用户当日数据

```
Key: user:{userId}:data:{date}
Type: Hash
TTL: 7天

Fields:
  - keyboard_count: 键盘敲击次数
  - mouse_click_count: 鼠标点击次数
  - mouse_distance: 鼠标移动距离
  - scroll_distance: 滚轮滚动距离
```

示例：
```
HSET user:12345:data:2026-07-14 keyboard_count 1250
HSET user:12345:data:2026-07-14 mouse_click_count 856
HSET user:12345:data:2026-07-14 mouse_distance "23.01"
```

#### 用户当日应用列表

```
Key: user:{userId}:apps:{date}
Type: Hash
TTL: 7天

Fields:
  - {app_name}: JSON格式的应用数据
```

示例：
```
HSET user:12345:apps:2026-07-14 Chrome '{"name":"Chrome","windowTitle":"Google搜索","duration":3600,"isActive":true}'
HSET user:12345:apps:2026-07-14 VSCode '{"name":"VSCode","windowTitle":"main.py","duration":1800,"isActive":false}'
```

### 4.2 Token黑名单（可选替代MySQL方案）

```
Key: token:blacklist:{jti}
Type: String
Value: "1"
TTL: Token剩余有效期
```

### 4.3 秘钥缓存

```
Key: secretkey:{secretKey}
Type: String
Value: userId
TTL: 24小时（可配置）
```

**说明**：缓存秘钥与用户ID的映射关系，加速验证。

### 4.4 在线用户集合

```
Key: online:users
Type: Set
Members: 在线用户的userId
```

### 4.5 用户订阅关系

```
Key: subscribe:user:{userId}
Type: Set
Members: 订阅该用户的session_id
```

**说明**：推送时通过此集合找到所有订阅者的WebSocket会话。

## 5. 数据流转流程

### 5.1 数据上传流程

```
客户端上传 → 后端接收 → 更新Redis热数据 → 记录数据日期索引 → 触发WebSocket推送
```

详细步骤：
1. 客户端每秒上传增量数据
2. 后端验证Token
3. 更新Redis中用户当日数据（Hash结构）
4. 更新/新增数据日期索引表
5. 查询订阅该用户的所有WebSocket会话
6. 推送完整实时数据给所有订阅者

### 5.2 数据归档流程

```
定时任务 → 查询Redis中7天前的数据 → 写入MySQL → 删除Redis数据
```

详细步骤：
1. 定时任务每天凌晨执行
2. 扫描Redis中超过7天的Key
3. 读取数据并聚合
4. 批量插入MySQL：
   - `daily_statistics`: 每日汇总
   - `app_usage_records`: 应用明细
   - `app_window_titles`: 窗口标题
5. 删除Redis中已归档的Key

### 5.3 历史数据查询流程

```
前端请求 → 判断日期 → Redis(近7天) / MySQL(超过7天) → 返回数据
```

## 6. 索引设计总结

### 6.1 MySQL索引

| 表名 | 索引名 | 索引列 | 类型 | 用途 |
|------|--------|--------|------|------|

| 数据类型 | Key格式 | 说明 |
|----------|---------|------|
| 用户日数据 | `user:{userId}:data:{date}` | 当日统计数据 |
| 应用列表 | `user:{userId}:apps:{date}` | 当日应用详情 |
| 秘钥缓存 | `secretkey:{secretKey}` | 秘钥映射 |
| Token黑名单 | `token:blacklist:{jti}` | Token失效 |

## 8. 性能优化建议

### 8.1 分表策略

当数据量增长时，考虑以下分表策略：

1. **按日期分表**：
   - `app_usage_records_202607`
   - `daily_statistics_202607`

2. **按用户ID分表**：
   - `app_usage_records_0` ~ `app_usage_records_15`（按用户ID取模）

### 8.2 归档策略

- 7天内数据存Redis
- 7天后归档到MySQL
- 1年后可考虑将数据归档到对象存储或冷数据库

### 8.3 查询优化

- 热数据全部从Redis读取
- 历史数据查询走索引
- 日历日期列表使用索引表，避免扫描大表
