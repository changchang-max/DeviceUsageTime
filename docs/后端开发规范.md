# 后端开发规范记忆文档

## 📌 重要配置说明

### 1. 路径前缀自动配置 (WebConfig.java)

项目中已在 `WebConfig.java` 配置了自动路径前缀：

```java
// controller.api包自动添加/api前缀
configurer.addPathPrefix(
    "/api",
    global_api -> global_api.getPackageName()
        .startsWith("top.primordialcode.backend.controller.api")
);

// controller.index包自动添加/index前缀
configurer.addPathPrefix(
    "/index",
    global_api -> global_api.getPackageName()
        .startsWith("top.primordialcode.backend.controller.index")
);
```

### 2. Controller 路径映射规则

**⚠️ 重要：在 controller.api 包下的控制器，@RequestMapping 中不要重复写 /api 前缀**

#### ✅ 正确写法：

```java
// 位置：controller/api/user/UserController.java
@RestController
@RequestMapping("/user")  // ✅ 不要写 /api/user
public class UserController {
    @GetMapping("/profile")  // 最终路径：/api/user/profile
    public Result getUserProfile() { ... }
}
```

```java
// 位置：controller/api/auth/LoginPageController.java
@RestController
@RequestMapping("/auth")  // ✅ 不要写 /api/auth
public class LoginPageController {
    @PostMapping("/login")  // 最终路径：/api/auth/login
    public Result login() { ... }
}
```

#### ❌ 错误写法：

```java
@RestController
@RequestMapping("/api/user")  // ❌ 重复了 /api，会导致路径变成 /api/api/user
public class UserController { ... }
```

### 3. 包结构与路径对应关系

| 包路径 | @RequestMapping 写法 | 实际访问路径 |
|--------|---------------------|-------------|
| `controller.api.auth` | `/auth` | `/api/auth` |
| `controller.api.user` | `/user` | `/api/user` |
| `controller.api.data` | `/data` | `/api/data` |
| `controller.index` | `/home` | `/index/home` |

### 4. 权限配置参考 (SecurityConfig.java)

```java
.authorizeHttpRequests(auth -> auth
    // ========== 公开接口(无需认证) ==========
    .requestMatchers(
        "/api/auth/login",
        "/api/auth/register",
        "/api/auth/sendCode",
        "/api/auth/verify-key",
        "/ws/**"
    ).permitAll()

    // ========== ROLE_USER角色专属接口 ==========
    .requestMatchers(
        "/api/auth/logout",
        "/api/data/**",
        "/index/home",
        "/api/user/**"
    ).hasAuthority("ROLE_USER")

    // ========== 其他未匹配的接口 ==========
    .anyRequest().denyAll()
)
```

## 📝 开发新接口的标准流程

### Step 1: VO 层（视图对象）
```java
// 位置：vo/user/UserProfileVO.java
package top.primordialcode.backend.vo.user;

import com.fasterxml.jackson.annotation.JsonProperty;
import lombok.Data;
import java.time.Instant;

/**
 * 用户档案信息返回VO
 */
@Data
public class UserProfileVO {
    private String email;
    
    @JsonProperty("secretKey")  // 自定义JSON字段名
    private String secretKey;
    
    private Instant createdAt;
    private Instant lastLoginAt;
}
```

**VO 类命名规范**：
- 用于接口返回：`XxxVO` 或 `XxxResponseVO`
- 放在 `vo` 包下，按模块分子包（如 `vo.user`、`vo.data`）

### Step 2: Mapper 层
```java
// 在 Mapper 接口中添加方法
UserAuthEntity selectProfileByEmail(String user_email);
```

### Step 3: Mapper XML
```xml
<!-- 在对应的 XML 文件中添加 SQL -->
<select id="selectProfileByEmail" resultType="UserAuthEntity">
    select user_email,user_key,user_name,created_at,last_login_at
    from user_auth
    where user_email = #{user_email}
</select>
```

### Step 4: Service 层
```java
@Slf4j
@Service
public class UserService {
    @Autowired
    private UserAuthMapper userAuthMapper;

    public UserAuthEntity getUserProfile(String email) {
        log.info("获取用户档案，邮箱：{}", email);
        UserAuthEntity user = userAuthMapper.selectProfileByEmail(email);
        if (user == null) {
            throw new RuntimeException("用户不存在");
        }
        return user;
    }
}
```

### Step 5: Controller 层
```java
@Slf4j
@RestController
@RequestMapping("/user")  // ⚠️ 不要写 /api/user
public class UserController {
    @Autowired
    private UserService userService;

    @GetMapping("/profile")
    public Result getUserProfile() {
        // 从 SecurityContext 获取当前用户
        Authentication auth = SecurityContextHolder
            .getContext()
            .getAuthentication();
        String email = (String) auth.getPrincipal();
        
        // 调用服务层
        UserAuthEntity user = userService.getUserProfile(email);
        
        // Entity 转 VO
        UserProfileVO profileVO = new UserProfileVO();
        profileVO.setEmail(user.getUser_email());
        profileVO.setSecretKey(user.getUser_key());
        profileVO.setCreatedAt(user.getCreated_at());
        profileVO.setLastLoginAt(user.getLast_login_at());
        
        return Result.success("获取成功", profileVO);
    }
}
```

### Step 6: 权限配置（如需要）
在 `SecurityConfig.java` 中添加路径权限配置

## 📊 DTO vs Entity vs VO 的区别

| 类型 | 用途 | 位置 | 特点 |
|------|------|------|------|
| **Entity** | 数据库映射 | `entity/` | 与数据库表结构一一对应，包含所有字段 |
| **DTO** | 接收请求参数 | `dto/` | 用于接收客户端传入的数据，可能包含验证注解 |
| **VO** | 返回响应数据 | `vo/` | 用于返回给客户端的数据，过滤敏感信息 |

### 示例说明

```java
// Entity - 完整的数据库表映射
@Data
public class UserAuthEntity {
    private String user_email;
    private String user_password;  // ⚠️ 包含密码
    private String user_key;
    private Instant created_at;
    private Instant last_login_at;
}

// DTO - 接收登录请求
@Data
public class LoginDTO {
    private String user_email;
    private String user_password;
}

// VO - 返回用户信息（不包含密码）
@Data
public class UserProfileVO {
    private String email;
    private String secretKey;
    private Instant createdAt;
    private Instant lastLoginAt;
    // ✅ 没有密码字段
}
```

## ⚡ 常见错误提醒

1. ❌ **在 controller.api 包下使用 `/api/xxx`**
   - 会导致路径变成 `/api/api/xxx`

2. ❌ **忘记配置 SecurityConfig 权限**
   - 新接口会被 `.anyRequest().denyAll()` 拦截

3. ❌ **直接返回 Entity 包含敏感信息**
   - ✅ 应使用 VO 类，过滤密码等敏感字段
   - ❌ 不要使用 Map 拼装数据（类型不安全）

4. ❌ **VO 类字段命名不规范**
   - ✅ 使用 `@JsonProperty("secretKey")` 控制 JSON 字段名
   - 保持 Java 命名规范（驼峰）的同时满足前端需求
